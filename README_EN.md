# Telegram Download Bot (aria2 + rclone)

Send a link to the bot → aria2 downloads it → rclone uploads it to your cloud drive → local file is deleted.

## Features

- `/mirror <link>`: download direct links, magnets, and `.torrent` links. You can also just send a link directly, or send a `.torrent` file. Multiple links in one message each become their own task.
- Live download progress (percent, speed, ETA, elapsed time); progress refreshes every 5 seconds.
- `/status`: view running tasks; `/cancel`: cancel a task (cleans up the unfinished local file synchronously).
- `/cleanup`: clean up orphan downloads in aria2 (tasks the bot lost track of after a restart while aria2 kept downloading).
- `/storage`: add a cloud drive, pick a default storage, change the save folder, delete a storage. For OAuth drives (OneDrive / Google Drive / Dropbox, etc.), click the login link, log in, and send the localhost redirect URL back to the bot. Other drives are configured with guided prompts. You can also import a remote already configured in rclone.conf via "Already configured in rclone (import)".
- Default storage: if set, uploads go straight there; if not set and you have several drives, the bot asks which one to use after each download finishes.
- If an upload fails, the local file is kept and the message has a retry button; failed downloads can be retried too.
- `/timezone`: set the timezone used for upload timestamps.
- Whitelist: only users in `ALLOWED_USER_IDS` can use the bot.
- Magnets: correctly follows aria2's metadata task (followedBy); seeding stops automatically after download (`--seed-time=0`) and triggers the upload.
- Tracker auto-update: pulls the latest best lists daily from both ngosang/trackerslist and adysec/tracker, merges and deduplicates them, and pushes them to the running aria2 without restarting it.

## Deploy

```bash
./setup.sh            # download aria2 and rclone static binaries into ./bin/, create .venv and install deps
cp .env.example .env  # fill in API_ID / API_HASH / BOT_TOKEN / ALLOWED_USER_IDS
.venv/bin/python app.py
```

The bot starts aria2c itself (RPC listens on 127.0.0.1:6800 only). If no aria2 secret is set, one is generated automatically and saved to `aria2-secret.txt` (chmod 600). See [DEPLOY_EN.md](DEPLOY_EN.md) for details.

## Files

| File | Purpose |
|---|---|
| `app.py` | Entry point: Telethon startup, whitelist, commands, message and callback handling |
| `tasks.py` | Download tasks: aria2 progress polling, upload, retry, cancel, local cleanup |
| `aria2rpc.py` | aria2 JSON-RPC client + daemon management (auto-starts aria2c) |
| `rclone.py` | rclone wrapper: config read/write, remote verification, directory ops, `rclone move` upload |
| `storage.py` | `/storage`: storage registry, OAuth flow, folder picker, add/change/delete |
| `auth.py` | Whitelist check (uses `sender_id` directly) |
| `config.py` | Environment variable configuration |
| `tzutil.py` | User timezones |
| `providers.json` | rclone backend registry for all 71 backends (generated by `rclone config providers`) |
| `setup.sh` | Download static binaries, create venv, install deps |
| `tests/` | Tests (see below) |

## Tests

```bash
.venv/bin/python tests/test_cleanup.py   # unit tests
python tests/smoke_test.py              # smoke test
```

The smoke test does not touch Telegram or any real server: it tests the aria2 client against a fake RPC server, and runs the full pipeline (download → move upload → verify remote file info → local cleanup) with real aria2c and real rclone (using an alias remote as the cloud drive).
